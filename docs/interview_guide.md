# 项目讲解与面试准备

这份材料解释项目中的具体取舍。简历数字以 `docs/evidence/` 中最后生成的真实回归证据为准；先亲自复跑一项测试、阅读波形和关键代码，再把它作为个人项目讲解。

## 如何讲清项目

可以按“对象—环境—检查—缺陷—证据”展开：验证 PULP 的 APB UART；搭建 APB 主设备 Agent 和 UART 外部设备 Agent；用两个方向的数据预测队列自动比对；通过需求测试复现逐帧错误标记和中断问题，在单独 RTL 修复版回归；用 Python 保存多 seed 结果、波形和测得的覆盖缺口。

区分工作来源：原始 UART RTL 来自上游开源项目；本项目包含自建验证环境、回归和证据工具，以及本地维护的 RTL 修复版。不要把原始控制器声称为自行设计，也不要把本地修复称为已经被上游接收。

## 为什么让 Monitor 产生期望值

TX 的参考数据来自 APB Monitor 看见的 THR 访问，RX 的参考数据来自 UART Monitor 对实际引脚的独立解码。Sequence 发出请求并不保证总线完成，Driver 产生数据也不保证引脚正确，因此直接以 Sequence 的意图作唯一真值会漏掉验证环境自身的问题。

Monitor 为每次观察创建独立事务。Scoreboard 不依赖 DUT 内部 FIFO 数组或状态机层次路径。APB 在下降沿驱动，上升沿读取接收前的值，避开和 RTL 非阻塞赋值更新同时采样造成的竞态。

## APB 与寄存器最容易问到的点

APB 传输包含 Setup（PSEL=1、PENABLE=0）和 Access（PSEL=1、PENABLE=1）阶段；只有 Access 且 PREADY 为 1 才完成。控制与写数据需在等待期间保持稳定。本 UART 恒 ready，不等于所有 APB 从设备都不需要等待。

此版本只译码 PADDR[2:0]，所以寄存器偏移是 0～7 而非通常示例中的 0、4、8。高位地址会形成镜像，验证必须由真实 RTL 和目标规格确定地址步长。

DLAB=LCR[7] 决定偏移 0/1 访问的是分频锁存器还是数据/中断使能。测试在收发前写 DLAB、DLL、DLM，再恢复格式；Scoreboard 跟踪这个映射，否则会把配置写当成待发送数据。

## 为什么 FIFO16 能暂存17帧

TX 还有一个发送移位寄存器：开始发送后，FIFO 可再装16字节，合计17帧未完成。短时间连续写21字节时，前17字节可被接收，之后4字节在 FIFO 满的条件下丢弃。PREADY 恒1只是表示 APB 访问完成，并没有表明数据进入 FIFO。

外部 TX 参考模型从 APB 访问和配置的帧周期推导 FIFO 占用与发送器忙周期。它先判断本周期开始时是否满，再处理出队和写入；原版 FIFO 在满且同周期出队时依然拒绝新写，不能简单“先减后加”。

RX 满时接收器会停留在 SAVE_DATA，额外一个完整帧可留在移位寄存器中，等读 RBR 腾出空间后入队。所以第17帧不应直接按丢弃建模；第18帧之后没有完整 overrun 处理，本项目明确限定其适用范围。

## 帧错误为什么需要逐字节关联

原版一方面把错误清除永久拉高，另一方面在校验阶段之前提交数据。只改一个清除常量不能保证错误位随正确的字节入队。

修复版在完成数据、校验、停止位检查后才提交 `{framing_error, parity_error, data}`。LSR 反映 FIFO 当前队首的标志，弹出后转到下一字节。通过“正常→错误→正常”排队再读出的测试，可以识别错误标志提前、延后或残留的问题。

## 中断为什么不能只看 event_o

多个来源同时存在时，确认一个来源后另一个来源可能继续保持 IRQ。因此同时检查 IIR 来源、使能、阈值与确认行为。项目的本地修复约定是线路错误优先于 RX 门限、RX 门限优先于 TX 空，读 LSR 确认当前队首线路错误，读 IIR 确认选中的 TX 空来源。

上游问题包括把 RX 的 RDA 接到 TX 空状态，以及清除时只做按位与而不恢复“无中断”位。测试需检查空 RX 时使能不产生假 IRQ、使能关闭后撤销，以及确认后下一次触发能重新出现。

## 复位会使哪些事务失效

帧中复位会取消正在发送或接收的部分帧，不能在复位后继续等待旧预测。Scoreboard 清空队列与参考状态，Monitor 丢弃部分帧，事务的 epoch 防止复位前的观察晚到后污染新队列。测试还需在复位后重新配置并检查新数据，单纯“复位后没有报错”不足以验证恢复能力。

## 覆盖率和通过率怎么讲

测试通过率表示本次列出的检查没有失败；不能推导为所有功能都正确。功能覆盖率按已定义的 coverpoint/bin 统计，代码覆盖率按 RTL 被执行的行或分支统计，两个分母不同。

Verilator 原生数据库中的可统计 bin 命中比例，与 SystemVerilog 的加权 covergroup API 不是同一指标。报告明确列出分子、分母、排除项与未命中项，避免只报一个没有定义的百分比。覆盖缺口先判断是否可达和是否在规格范围，再决定补激励还是记录理由。

随机 seed 决定刺激序列。压力测试还保存数据与格式摘要，便于确认不同 seed 确实产生不同刺激；固定 seed 和相同源码可以复现问题。失败原始日志保留，不因后续修复而被改写成 PASS。

## 项目边界应主动说明

实际运行过的仿真器与 UVM 版本见验证记录。Questa/VCS 入口不等于这两种商业工具已经执行过。没有实现的完整16550功能、极小分频、任意配置热切换或波特率容差，不能据现有测试声称通过。

一个可信的项目讲解应能打开一条失败日志指出检查点，再打开修复代码、相同需求的通过日志和波形，解释改变的行为与剩余限制。
