# 独立修复版本：错误标记与中断

`rtl/` 保留 PULP Platform `apb_uart_sv` 提交 `dfad6e04d19cc9481d3cd2750b45b970dc61271b` 的原始文件。`rtl_fixed/` 是此验证项目的本地修复版本，并非上游已经接收的修改。两个目录里的模块名称相同，每次编译只能选一个目录。顶层 `apb_uart_sv` 的 APB、UART 与中断端口不变。

本次修改针对 [`rtl_findings.md`](rtl_findings.md) 中经代码确认的 F01～F04，并补足错误结果与相应字节的关联时序。没有把该设计扩展成完整的 16550 实现。

最终动态证据已完成：修复版 15 场景×3 seed 全部通过，原版严格需求出现 12 次真实功能失败；完整统计见 [验证记录](validation.md)。以下行为约定和范围边界保持不变。

## RX 帧与错误状态

接收流程为 `IDLE → START_BIT → DATA → [PARITY] → STOP_BIT → SAVE_DATA`。UART 输入先经过三级同步；检测到下降沿后，在起始位中点确认输入为低。之后每隔 `D+1` 个时钟采样一个数据位，启用校验时再采样偶校验位，最后验证第一个停止位为高。

只有完成停止位检查后才置 `rx_valid_o`。`rx_data_o`、`err_o` 和新增的内部端口 `framing_err_o` 在 valid 等待期间保持对应同一帧；RX FIFO 准备好时一同入队。顶层把 `err_clr_i` 接 0，避免原来固定清零把错误压掉；接收器在每个新帧开始时初始化该帧的两个标记。

LSR 的实际约定如下：

- `[0]`：RX FIFO 非空。
- `[2]`：当前队首字节有偶校验错误。
- `[3]`：当前队首字节的第一个停止位为低。
- 空 FIFO 的 `[2:3]` 为 0，不暴露 FIFO 数组中的历史错误。
- 读取 LSR 可以确认线路错误中断，但不会清掉队首字节携带的错误标记。弹出 RBR 后，LSR 随新的队首更新；清空 FIFO 或复位也使这些位恢复 0。LSR 仍通过原有寄存器更新，测试应给状态更新留时钟余量。

相邻两个错误帧分别保存自己的标记；第一个帧的校验错误不应跑到第二个字节上。短低脉冲若在起始位中点前恢复为高，会被丢弃。当前仍只检查第一个停止位，接受发送端的 1 或 2 个高停止位，不提供第二停止位的独立诊断。

## 中断约定

保留上游项目所使用的 IIR 编码，未改成标准 16550 的完整编码体系。IIR 高四位仍为 `0xC`。

| 优先级 | 条件 | IIR 读值 | 撤销 / 确认行为 |
| --- | --- | --- | --- |
| 高 | IER `[2]` 使能，当前 RX 队首有 PE 或 FE，且尚未确认 | `0xCC` | 读 LSR 确认该队首错误的中断；弹出 RBR 为下一队首重新使能错误通知；关闭 IER `[2]` 立即撤销该来源 |
| 中 | IER `[0]` 使能，RX 非空且 FIFO 占用数达到 FCR 门限 | `0xC8` | 电平条件；RBR 读使占用数降到门限以下才撤销；读 IIR 不隐藏仍满足门限的 RX 来源 |
| 低 | IER `[1]` 使能，TX FIFO 为空，且空状态尚未确认 | `0xC4` | 当 IIR 当前选中此来源时，读 IIR 确认；后续 TX FIFO 曾经非空，或关闭再开启 IER `[1]`，会重新使能下一次空通知 |
| 无 | 没有满足条件的已使能来源 | `0xC1` | `event_o=0` |

FCR `[7:6]` 的门限分别为 1、4、8、14；比较使用 `>=`，达到门限后继续入队不会让中断消失。IER 全为 0 时没有中断；RX 为空且只开启接收中断时也没有事件。中断输出由当前最高优先级来源决定，确认一个来源后，较低优先级仍可能让 `event_o` 保持为 1；测试须同时核对 IIR。

线路错误确认是针对当前队首的通知抑制。RBR 弹出后立即重新允许下一队首通知，因此连续两个错误帧不需要中间出现一个正常帧。读取 LSR 不会误确认 TX 空来源。字符超时输入仍在顶层固定为 0，没有新增字符超时功能。

## 保留的边界

- APB 地址仍为 0～7 字节连续译码，PREADY 恒 1，满 TX FIFO 写入仍被忽略，没有错误响应或总线等待。
- FIFO 深度仍为 16。RX FIFO 满时，一个额外的完整帧会停在 `SAVE_DATA` 等待空间，即可保存第 17 帧；此后继续到来的串行帧无法保证接收，没有 overrun 标志。
- FCR 只清 FIFO，不中止串行状态机。若已经有第 17 个帧等待，清 FIFO 后该帧仍可能入队。验证该情况应使用独立的时序模型。
- 分频仍使用 `D+1` 个时钟的位周期，TX 未改变。RX 数据位、校验位和停止位按此周期采样；基础验证使用 `D>=31`。未承诺零分频、极小分频、传输中改配置或任意波特率偏差的正确性。
- 只有偶校验；MCR/MSR/SCR、break、完整调制解调器控制、线路错误汇总位及完整 16550 软件兼容性不在修改范围内。

## 验证要求与证据边界

代码提交时已用本地 pyslang 对修复版 5 个 RTL 文件做语义编译，结果为 **0 errors、0 warnings**。这只证明源码可解析、连接和类型检查通过，不能代替动态仿真。

动态回归应至少包含下列互相独立的检查；实际执行结果以回归产物为准，本文件不预先声称这些场景已通过：

1. 5～8 位、偶校验开关、1/2 停止位的正常收发，确保接收流程改变后数据路径未退化。
2. 校验错误、停止位错误，以及正常/错误帧交错、连续错误帧，逐个读取 LSR 和 RBR，确认标记与字节对应。
3. 空 RX 时打开 IER `[0]` 无中断；四个 FCR 门限均在 `门限-1`、`门限`、`门限+1` 检查 IIR/事件，排空后撤销。
4. 只开启 TX 空中断时触发一次，读 IIR 后得到无中断编码；发送数据并排空后重新触发；禁用使能后撤销。
5. 同时存在 RX、TX 空和线路错误时检查优先级；读 LSR 只确认线路错误中断，RBR 弹出后下一错误字节能再触发。
6. FIFO 满空、指针环绕、RX 第 17 帧保留、FIFO 清除和帧中复位；复位后不能残留错误标记或已确认状态。
7. 在原版运行严格错误报告要求应失败，在修复版通过；原版的缺陷特征测试与修复版的功能要求测试必须清楚区分。
