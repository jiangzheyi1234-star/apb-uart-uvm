# 实测覆盖缺口分析

统计对象为修复版核心回归的 15 场景 × seed 1/2/3，共 45 次 PASS 运行。数据来自 [发布报告](release/index.html) 中保存的原生合并覆盖数据库及 LCOV；RAL 专项、检查器敏感性实验和上游对照不并入以下分母。

## 功能覆盖

功能 bins 未加权命中率为 **272/277，98.19%**。每个有效 bin 按其 `at_least` 阈值判断是否命中；这与加权的 SystemVerilog covergroup API 百分比是不同统计口径。

| 覆盖项目 | 对应检查 | 实测情况 |
| --- | --- | --- |
| DLAB bank、寄存器读/写和地址镜像交叉 | 在两套 bank、低地址和高位镜像逐个访问寄存器；保持 DLL=31、DLM=0、IER=0；检查只读写忽略、空读不下溢和 bank 保持 | 总线访问与镜像交叉全部命中 |
| IER 的 3/5/6 组合 | 检查空 RX 时最高有效中断来源、IIR 编码、确认与禁用后撤销 | 组合全部命中 |
| 线路错误与 TX 空来源在不同 RX 门限下的交叉 | 四档门限分别触发 TX 空通知及错误队首通知，核对确认和状态保持 | 可达中断交叉全部命中 |

帧格式交叉为 **32/32**，增加波特周期后为 **96/96**，二者均实际命中 100%。三个周期为 32/48/64 个时钟，每个包含双向、5～8 数据位、校验开关和 1/2 停止位。

## 保留的五个未命中诊断 bin

剩余项为：

1. `interrupt_cg.source.invalid_pending`。
2. 上述无效编码与门限 0 的交叉。
3. 与门限 1 的交叉。
4. 与门限 2 的交叉。
5. 与门限 3 的交叉。

这些项用于观察原版可能产生的无效 pending 编码。修复版只从无中断 1、TX 空 4、RX 门限 8、线路错误 C 中选择，正确运行不应命中无效编码。因此保留为未命中，报告仍用 277 作分母，不把覆盖组改成 100%。

`payload.other` 和 `bit_period.other` 是 default bins，按 SystemVerilog 默认 bin 统计规则不纳入命中率。统计未增加 ignore/illegal/零权重排除；五个未命中诊断 bin 继续保留在 277 的分母中。

## 代码覆盖率边界

修复版 RTL LCOV 行命中为 **453/474，95.57%**，分支为 **1,670/2,120，78.77%**。没有用功能覆盖率代替分支指标。

剩余行主要涉及固定输入下不可激励的接收关闭/外部错误清除、字符超时输入、合法状态编码下的 default 恢复、常量/未使用接口信号，以及未激励的短起始位毛刺拒绝路径。原生 LCOV 保留这些行的计数，没有手工修改数据库或排除它们。

当前验收不包含完整四态/X 传播、任意配置热切换、任意波特率失配、活跃 TX 中清 FIFO、RX 超过第17帧后的连续过载和完整16550功能。它们不能由现有覆盖率推断为已通过。

工具版本、两套 RTL 的运行结果和覆盖合并检查见 [验证结果](validation.md)。证据包下载及离线目录恢复方法见 [发布说明](../RELEASE.md)；源码 ZIP 本身不包含生成的覆盖数据库和报告。
