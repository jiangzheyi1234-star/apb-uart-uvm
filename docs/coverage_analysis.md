# 实测覆盖缺口分析

统计对象为 [完整 CI 45321619200](https://github.com/jiangzheyi1234-star/apb-uart-uvm/actions/runs/45321619200) 中修复版核心回归的 15 场景 × seed 1/2/3，共 45 次 PASS 运行，受测提交 `127f21e0d695cd0e6aa32b46541b158196058679`。数据来自 [发布报告](release/index.html) 中保存的原生合并覆盖数据库及 LCOV；RAL 专项、检查器敏感性实验、独立 APB 协议和上游对照不并入以下分母。

## 功能覆盖

功能 bins 未加权命中率为 **272/277，98.19%**。每个有效 bin 按其 `at_least` 阈值判断是否命中；这与加权的 SystemVerilog covergroup API 百分比是不同统计口径。

| 覆盖项目 | 对应检查 | 实测情况 |
| --- | --- | --- |
| DLAB bank、寄存器读/写和地址镜像交叉 | 在两套 bank、低地址和高位镜像逐个访问寄存器；保持 DLL=31、DLM=0、IER=0；检查只读写忽略、空读不下溢和 bank 保持 | 总线访问与镜像交叉全部命中 |
| IER 的 3/5/6 组合 | 检查空 RX 时最高有效中断来源、IIR 编码、确认与禁用后撤销 | 组合全部命中 |
| 线路错误与 TX 空来源在不同 RX 门限下的交叉 | 四档门限分别触发 TX 空通知及错误队首通知，核对确认和状态保持 | 可达中断交叉全部命中 |

帧格式交叉为 **32/32**，增加波特周期后为 **96/96**，二者均实际命中 100%。三个周期为 32/48/64 个时钟，每个包含双向、5～8 数据位、校验开关和 1/2 停止位。

## 保留的五个未命中诊断 bin

剩余项为：

1. `interrupt_cg.source.invalid_pending`。
2. 上述无效编码与门限 0 的交叉。
3. 与门限 1 的交叉。
4. 与门限 2 的交叉。
5. 与门限 3 的交叉。

这些项用于观察原版可能产生的无效 pending 编码。修复版只从无中断 1、TX 空 4、RX 门限 8、线路错误 C 中选择，正确运行不应命中无效编码。因此保留为未命中，报告仍用 277 作分母，不把覆盖组改成 100%。

`payload.other` 和 `bit_period.other` 是 default bins，按 SystemVerilog 默认 bin 统计规则不纳入命中率。统计未增加 ignore/illegal/零权重排除；五个未命中诊断 bin 继续保留在 277 的分母中。

## 代码覆盖率边界

修复版 RTL LCOV 行命中为 **453/474，95.57%**，分支记录命中为 **1,670/2,120，78.77%**。Verilator 的 LCOV 导出可将多个覆盖点映射到同一源码行。分支列逐条统计导出的 `BRDA` 记录。[Verilator 覆盖导出](https://verilator.org/guide/latest/exe_verilator_coverage.html)

剩余行主要涉及固定输入下不可激励的接收关闭/外部错误清除、字符超时输入、合法状态编码下的 default 恢复、常量/未使用接口信号，以及未激励的短起始位毛刺拒绝路径。原生 LCOV 保留这些行的计数，没有手工修改数据库或排除它们。

当前验收不包含完整四态/X 传播、任意配置热切换、任意波特率失配、活跃 TX 中清 FIFO、RX 超过第17帧后的连续过载和完整16550功能。它们不能由现有覆盖率推断为已通过。

### 按 RTL 文件复核缺口

工作台覆盖页的“RTL 源码”模式按文件显示行、分支各自的命中数与总数。选择文件后，可查看完整未命中行/分支明细，并通过行号打开固定受测提交的源码；“功能缺口”模式在同一区域查看 covergroup bin、阈值和原因。文件列表及明细只统计当前报告的 LCOV 记录，未插桩的源码行不自动计作缺口。切换报告时，套件、RTL 版本和对应明细保持一致；各报告原始计数与分母保持不变。修复版核心的五个未命中诊断 bin 仍保留在分母中，没有增加豁免。

这一路径参考 [Verilator 覆盖工具](https://verilator.org/guide/latest/exe_verilator_coverage.html) 的源码标注及 LCOV 导出方式，用于从合并指标定位到源文件和覆盖点。界面操作与证据生成见 [工作台说明](dashboard.md#覆盖与源码下钻)。

## 独立协议验证的范围

同次 CI 的 APB Agent 协议审计覆盖 0/1/3/7 个等待周期、PSLVERR、复位中止、超时边界和恢复：9 次正向 PASS、3 次超时原始 FAIL/DETECTED、3 次正常恢复 PASS。UART 的 `PREADY` 恒为 1，这些行为通过独立可编程从设备激励。协议结果证明所选 Agent 场景通过审计，不表示 UART DUT 的等待路径被激励，也不增加本页 277 个功能 bin 或 RTL LCOV 分母。

UART 核心与 RAL 合计 48/48 PASS；协议 15 次、检查器 10 次及上游 45 次分别保留结果。RAL 的零 `[RegModel]` 初始化警告说明建模生命周期问题已消除，不代表配置值、并发组合或全部寄存器副作用已穷举。协议本身也未穷举所有等待长度、复位相位或仲裁组合。详见 [验证结果](validation.md) 与 [协议说明](apb_protocol.md)。

工具版本、两套 RTL 的运行结果和覆盖合并检查见 [验证结果](validation.md)。证据包下载及离线目录恢复方法见 [发布说明](../RELEASE.md)；源码 ZIP 本身不包含生成的覆盖数据库和报告。
