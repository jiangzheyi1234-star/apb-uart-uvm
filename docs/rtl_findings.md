# RTL 审阅发现与验证边界

审阅对象：PULP Platform [`apb_uart_sv`](https://github.com/pulp-platform/apb_uart_sv/tree/dfad6e04d19cc9481d3cd2750b45b970dc61271b)，提交 `dfad6e04d19cc9481d3cd2750b45b970dc61271b`，本地文件为 `rtl/` 下的原始源码。本文件记录静态审阅依据；最终动态复现、修复回归和真实覆盖结果见 [验证记录](validation.md)。原版 RTL 保留不变，本地修复位于独立目录。

## F01：RX 校验错误被永久清零

`rtl/apb_uart.sv:92` 把 `uart_rx.err_clr_i` 固定接为 `1'b1`。`rtl/uart_rx.sv:246` 先判断 `err_clr_i` 并清 `err_o`，只有其为 0 时才可能响应 `set_error`。因此当前集成下错误输出一直为 0，注入错误偶校验的帧也不会使 LSR `[2]` 置位。

另外，`uart_rx` 在 `SAVE_DATA` 阶段就让 `rx_valid_o` 为 1 并向 FIFO 提交数据（`:132`），之后才进入 `PARITY` 阶段（`:142`）。即使修正清除接线，仍需重新设计或验证“校验结果与对应字节一起入 FIFO”的时序，不能只改一个常量就宣布修复完成。

验证要求：错误帧注入与串行监视器错误识别可以被覆盖；**“DUT 正确报告校验错误”目前不能算通过**。若测试要求 LSR `[2]` 置位，应产生明确失败；如果测试仅做当前行为的特征检查，应在测试名和报告中标明这一范围。

建议后续修复方向：先完成数据位与校验位的接收，再携带该帧的错误标记提交 FIFO，错误清除动作使用明确握手。

## F02：RX 没有停止位检查或 framing error 状态

`rtl/uart_rx.sv:152` 的 `STOP_BIT` 只等待 `bit_done` 后回到 IDLE，没有检查串行输入是否为高。顶层也没有接 RX 停止位数量，LSR 没有 framing/overrun/break 标志更新。

验证要求：可在引脚监视器中检测低停止位并记录注入覆盖；不能把它宣传为验证了 DUT 的 framing error 上报功能。由于低停止位也会影响后续下降沿检测，错误帧后须留高电平空闲间隔，再开始下一帧。

## F03：接收中断的 RDA 输入接到 TX 空状态

`rtl/apb_uart.sv:176` 为 `.RDA_i(regs_n[LSR][5])`。而 `LSR[5]` 在 `:211` 定义为 TX FIFO 空，真正的 RX FIFO 非空信号在 `[0]`（`:205`）。`rtl/uart_interrupt.sv:72` 在 `IER[0]` 为 1 且 RDA 为 1 时产生接收中断。

可复现场景：复位后不注入 RX 帧，只使能 IER `[0]`；TX FIFO 原本为空，代码会触发接收中断。应把这作为独立的 DUT 缺陷测试，而不是让基础收发场景依赖它。基础场景使用轮询 LSR，并保持 IER 为 0。

## F04：中断清除未恢复无中断编码

`rtl/uart_interrupt.sv:87` 复位 `iir_q=4'b0001`，`event_o=~iir_q[0]`（`:96`）。发生中断后，编码例如为 `1000` 或 `0100`（最低位为 0）。清除路径只计算 `iir_q & ~clr_int_i`（`:66`），会得到 `0000`，不会把最低位恢复为 1。后续若没有其他来源更新该位，`event_o` 会保持为 1。

此外清除与事件同时发生时，后面的中断条件会重新覆盖清除结果；这对持续的 TX 空来源可能是预期的电平重触发，但不能解释 `0000` 仍被当作有中断的情况。中断编码也与标准 16550 不一致。

验证要求：中断首次触发、来源优先级、读 IIR/LSR/RBR 的清除行为与解除使能后中断撤销，都应作为后续专门的中断验证矩阵；当前基础环境不能据正常数据收发推断这些功能正确。

## F05：FIFO 满时的行为需要区分 TX 与 RX

TX：`rtl/io_generic_fifo.sv:83` 仅在 `valid_i && !full` 时写数组；`:137` 的 `ready_o=~full`。顶层没有把 ready 接到 APB 等待状态，`PREADY` 恒 1。满时 THR 写被静默丢弃，满且同周期出队也不接收新字节。

RX：同一 FIFO 的 ready 连接到 `uart_rx.rx_ready_i`。`rtl/uart_rx.sv:132` 在 `SAVE_DATA` 保持 valid，直到 ready 才进入校验/停止阶段。因此第 17 个帧可能暂存在接收移位寄存器中，并在软件读出一个 FIFO 元素后补入 FIFO。继续发送时无法保证处理第 18 帧等后续输入。RX 没有 overrun 标志。

验证要求：基础 RX 容量场景最多先注入 16 帧；超过容量须单独建模并记录当前实现行为。TX 满写测试应使用足够慢的波特率来保证写入期间不跨过多个帧，并考虑移位寄存器中的一个字节。

## F06：功能子集与时序偏差

- 只有偶校验，LCR `[4:6]` 无数据路径功能；MCR/MSR/SCR 未实现普通访问。
- 分频 `D` 的稳态位周期为 `D+1` 时钟。TX 在起始位上启用计数，并通过寄存的 `bit_done` 切换状态，因此首起始位可能为 `D+2` 时钟；后续数据位通常为 `D+1`。
- RX 有三位同步链和半位计数阶段；较小 `D` 时同步与寄存延迟占比很高。基础测试建议 `D>=31`，精确波特容差和极小分频应另行测试。
- RX 起始位阶段没有对中点电平做有效性确认，短低脉冲可能启动接收；应另测 glitch rejection。
- LSR 状态由寄存器更新，相对 FIFO 变化有延迟。FCR FIFO 清除为寄存脉冲，且不取消正在传输的帧。
- FIFO 数组在 FCR 清除时不擦除，空 RBR 可能返回历史数据；空读测试应检查计数/有效状态不下溢，而不是硬性要求返回零。

来源：`rtl/apb_uart.sv:84`、`:107`、`:205`、`:244`、`:266`；`rtl/uart_tx.sv:181`；`rtl/uart_rx.sv:93`、`:189`、`:202`；`rtl/io_generic_fifo.sv:74`。
